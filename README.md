# CS 230 – The Gaming Room Software Design

The Gaming Room was a client looking to expand its existing Android game, *Draw It or Lose It*, into a web-based application that could run across multiple platforms. The application needed to support multiple games, teams, and players while ensuring that names remained unique and game information stayed consistent. Throughout this project, I focused on creating a software design that met those requirements while also considering security, scalability, and overall performance. I think one of the things I did particularly well was organizing the different components of the application and explaining how they would work together. Creating the UML diagram helped me understand the relationships between the classes and how concepts like inheritance and the Singleton design pattern could be used to manage game data. Working through the design document also showed me how important it is to plan before writing code. Having the requirements and class structure laid out made it easier to understand how the application should function and helped identify potential issues early in the development process.

My approach to designing the software started with understanding the client's needs and breaking them down into smaller technical requirements. I compared different operating platforms and recommended Linux for the server because of its flexibility, lower operating costs, and support for Java applications. I also recommended a browser-based client so users could access the game from different devices without needing separate applications. Considering the user's needs was important because the design had to be practical and meet the client's expectations, not just work from a technical standpoint. If I could revise one part of my design document, I would expand the system architecture section by including a more detailed diagram showing how the browser, server, database, and storage components communicate. This would make the design easier for other developers to follow. In future projects, I plan to continue using UML diagrams, object-oriented design principles, and platform comparisons to guide my decisions. I would also spend more time considering security, scalability, and how the system would handle multiple users. Overall, this project helped me better understand how planning and documentation contribute to developing software that is organized, maintainable, and designed around the client's needs.
